# Downloader

Менеджер завантажень для Windows: сегментоване качання з докачуванням,
HLS/DASH, YouTube. Аналог IDM та Ant Download Manager.

![Архітектура](docs/architecture.png)

Інтерактивна схема: [відкрити в браузері](https://riasj1dar.github.io/downloader/architecture.html)
(на GitHub файл показує код, не сторінку). Джерело схеми — `docs/architecture.json`.

## Що вміє

- **Сегментоване качання** з динамічним поділом: вільний потік забирає
  половину залишку в найповільнішого, тож хвіст не тримає всю чергу.
- **Докачування після обриву** — і після вбивства процесу. Стан лежить
  поруч із файлом, а порядок запису такий: дані → `sync` → стан. Тому стан
  відстає від даних і ніколи їх не випереджає.
- **HLS і DASH**: вибір якості з маніфесту, злиття сегментів, окремі
  доріжки звуку зводяться в один файл.
- **YouTube** через yt-dlp, теж із вибором якості.
- **Розширення для браузера**: перехоплює завантаження, показує кнопку на
  `<video>`, підхоплює `.m3u8` і `.mpd` зі сторінки.
- **Черга** з лімітами швидкості, розкладом і післядією (сон, вимкнення).
- **Інтерфейс**: вікно на Avalonia зі смужкою сегментів і графіком
  швидкості, командний рядок, українська та англійська мови.

## Встановлення

Два пакети, різниця одна — ffmpeg:

| | розмір | коли брати |
|---|---|---|
| `Downloader-X.Y.Z-web.msi` | 43 МБ | звичайний випадок: ffmpeg довантажиться командою `dl ffmpeg-install` |
| `Downloader-X.Y.Z-full.msi` | 95 МБ | машина без мережі або роздача офлайн |

Ставиться **для користувача**, у `%LOCALAPPDATA%\Programs\Downloader`, без
UAC і без служби. Вікно йде з .NET усередині — доставляти рантайм не треба.

⚠️ Пакети **не підписані**: сертифіката підпису коду немає, тож SmartScreen
попереджатиме при першому запуску. Натомість до кожного випуску йде
`SHA256SUMS.txt`, а самі пакети збираються в публічному CI з цього ж коду —
тож зібрати їх самому й звірити суми може будь-хто:

```
sha256sum -c SHA256SUMS.txt
```

### Навіщо ffmpeg

Без нього YouTube не завантажується взагалі. Відео й звук роздаються
**окремими доріжками** — навіть 144p не існує одним файлом, — і звести їх
більше нічим. DASH так само віддає звук окремим потоком.

Береться **LGPL**-збірка, без ключа `enable-gpl`. Це не дрібниця: GPL-варіант
зобов'язав би відкрити вихідний код усієї програми кожному, кому її дали.
LGPL такої вимоги не має, а ffmpeg тут ще й не лінкується в код — він
запускається окремим процесом. Текст ліцензії їде поруч, у
`LICENSE-ffmpeg.txt`.

## Командний рядок

Консольний клієнт — `dl`. Він уміє все, що вміє вікно. Швидкий старт:

```
dl get https://example.com/file.zip -o file.zip
```

`dl get` качає сам, у цьому вікні консолі. Решта команд керує **ядром** (`downloader-core`,
живе у треї): завдання, передане через `dl add`, переживе закриття консолі.

```
downloader-core
dl add https://example.com/file.zip
dl variants https://cdn.example/master.m3u8
dl get https://cdn.example/master.m3u8 -o video.mp4 --variant 720p.ts
dl list
dl watch
```

### Команди

| Команда | Що робить |
|---|---|
| `dl get <URL>` | завантажити файл просто в цьому процесі |
| `dl probe <URL>` | показати, що відомо про посилання, нічого не качаючи |
| `dl variants <URL>` | показати варіанти якості (HLS, DASH, YouTube); ядро не потрібне |
| `dl add [URL]` | передати завантаження ядру |
| `dl list` | показати завдання ядра |
| `dl parts <ID>` | показати, як завдання поділене на частини (те, що смужка сегментів у вікні) |
| `dl pause <ID>` | зупинити завдання |
| `dl resume <ID>` | продовжити зупинене завдання |
| `dl rm <ID> [--with-file]` | прибрати завдання зі списку; `--with-file` видаляє й уже завантажені байти |
| `dl move <ID> -q <ЧЕРГА>` | перемістити завдання в іншу чергу |
| `dl watch` | стежити за прогресом, доки не натиснуто Ctrl+C |
| `dl settings` | показати правила ядра: черга, ліміт, розклад, післядія |
| `dl configure …` | змінити правила ядра |
| `dl queue …` | керувати іменованими чергами |
| `dl ffmpeg-install` | поставити ffmpeg поруч із програмою |
| `dl ytdlp-update` | оновити yt-dlp (`yt-dlp -U`) |
| `dl update` | перевірити, чи є новіша версія (лише перевірка, нічого не ставить) |
| `dl completions <SHELL>` | згенерувати автодоповнення: `pwsh`, `bash`, `zsh`, `fish`, `elvish` |

`<ID>` — ідентифікатор зі `dl list`. `dl --version` показує версію, `dl <команда> --help` — довідку.

### Прапорці

Спільний для всіх команд — `--lang uk|en`.

**`dl get <URL>`**

| Прапорець | Типово | Значення |
|---|---|---|
| `-o, --out <ФАЙЛ>` | — | куди зберегти; без нього ім'я береться з `Content-Disposition` або з URL |
| `-n, --parts <N>` | `8` | скільки з'єднань відкривати |
| `--min-chunk <БАЙТИ>` | `1048576` | найменший шматок на з'єднання |
| `--limit-kb <КБ/с>` | `0` | стеля швидкості; `0` — без обмежень |
| `--checkpoint-ms <МС>` | `2000` | як часто скидати стан на диск |
| `--cookie <РЯДОК>` | — | заголовок Cookie: `n=v; n2=v2` |
| `--referer <URL>` | — | заголовок Referer |
| `--variant <ID>` | — | варіант якості: значення з першого стовпця `dl variants` |
| `--duration <ЧАС>` | — | обмеження тривалості live-потоку: `30s`, `10m`, `1h` |
| `--rewind` | — | почати live-потік від початку буфера (DVR) |

**`dl add [URL]`** — адреса може бути шаблоном `file[001-010].zip`, він розгортається у список.

| Прапорець | Значення |
|---|---|
| `--list <ФАЙЛ>` | файл зі списком адрес (по одній у рядку, `#` — коментар) |
| `--clipboard` | взяти адреси з буфера обміну |
| `-o, --out <ФАЙЛ>` | куди зберегти; для кількох адрес ігнорується |
| `-n, --parts <N>` | скільки з'єднань |
| `-q, --queue <ЧЕРГА>` | черга, типово `default` |
| `--cookie`, `--referer`, `--duration`, `--rewind` | як у `dl get` |

**`dl variants <URL>`** приймає `--cookie` і `--referer`.

**`dl configure`** — порожній прапорець поле не змінює.

| Прапорець | Значення |
|---|---|
| `--max <N>` | скільки завдань качати одночасно |
| `--rate-kb <КБ/с>` | стеля швидкості; `0` — без обмеження |
| `--after <ДІЯ>` | після порожньої черги: `none`, `sleep` або `shutdown` |
| `--from <ГГ:ХХ>`, `--to <ГГ:ХХ>` | вікно, коли дозволено стартувати завдання |
| `--clear-schedule` | прибрати розклад (качати завжди) |
| `--quiet-from <ГГ:ХХ>`, `--quiet-to <ГГ:ХХ>` | нічний профіль швидкості |
| `--quiet-kb <КБ/с>` | нічний ліміт; `0` вимикає нічний профіль |
| `--clear-quiet` | прибрати нічний профіль |

**`dl queue`**

| Команда | Значення |
|---|---|
| `dl queue list` | список черг |
| `dl queue add <НАЗВА> [опції]` | створити чергу |
| `dl queue set <НАЗВА> [опції] [--clear-schedule]` | змінити налаштування черги |
| `dl queue pause <НАЗВА>` / `resume <НАЗВА>` | зупинити / продовжити всі завдання черги |
| `dl queue rename <СТАРА> <НОВА>` | перейменувати |
| `dl queue rm <НАЗВА>` | видалити; завдання переходять у `default` |

Опції черги: `--max <N>`, `--rate-kb <КБ/с>`, `--from <ГГ:ХХ>`, `--to <ГГ:ХХ>`,
`--after none|sleep|shutdown`. Чергу `default` не можна видалити чи перейменувати.

**`dl update`**

| Прапорець | Значення |
|---|---|
| `--check [true\|false]` | лише перевірити й звірити хеші (типово `true`) |
| `--manifest <ШЛЯХ\|URL>` | локальний файл або адреса маніфесту оновлень |
| `--verify-file <ФАЙЛ>` | звірити SHA-256 завантаженого файлу з маніфестом |

**Автодоповнення** для PowerShell:

```
dl completions pwsh | Out-String | Invoke-Expression
```

### Змінні середовища

| Змінна | Значення |
|---|---|
| `DOWNLOADER_LANG` | `uk` або `en`; те саме, що `--lang` |
| `DOWNLOADER_PROXY` | проксі для HTTP (`http://…` або `socks5://…`); `none` або порожньо — без проксі. Без неї береться `HTTPS_PROXY` / `HTTP_PROXY` |
| `DOWNLOADER_MAX_CONCURRENT` | ядро: скільки завдань одночасно, перекриває збережене налаштування |
| `DOWNLOADER_RATE_LIMIT` | ядро: стеля швидкості в **байтах** за секунду, перекриває збережене |
| `DOWNLOADER_WATCH_CLIPBOARD` | `0` — ядро не стежить за буфером обміну |
| `DOWNLOADER_POST_DELAY_MS` | пауза перед післядією (сон / вимкнення), типово 60000 |
| `DOWNLOADER_POST_ACTION_DRY` | `1` — післядію лише імітувати (для перевірки) |

Мова без прапорця й змінної — мова ОС; для російської ОС і решти мов — українська.

### Де лежать дані

| Що | Звичайний режим | Портативний режим |
|---|---|---|
| Програма | `%LOCALAPPDATA%\Programs\Downloader` | будь-яка тека з файлом `portable.txt` |
| Завдання й налаштування | `%LOCALAPPDATA%\Downloader\tasks.db` | `<тека програми>\tasks.db` |
| Тема вікна | `%LOCALAPPDATA%\Downloader\ui.json` | `<тека програми>\ui.json` |
| Завантаження | `%USERPROFILE%\Downloads` | `<тека програми>\Downloads` |

Портативний режим вмикається порожнім файлом `portable.txt` поруч із `dl.exe`, `downloader-core.exe`
і `Downloader.Ui.exe`. Докладніше — [INSTALL.txt](INSTALL.txt).

### Ядро та native host

```
downloader-core [--db <ФАЙЛ>] [--downloads <ТЕКА>] [--pipe <ІМ'Я>] [--lang uk|en]
```

| Прапорець | Значення |
|---|---|
| `--db <ФАЙЛ>` | інший файл бази завдань |
| `--downloads <ТЕКА>` | куди класти файли без явного шляху |
| `--pipe <ІМ'Я>` | інше ім'я каналу — для тестів і кількох незалежних екземплярів |
| `--lang uk\|en` | мова трею й повідомлень |

Докладність журналу ядра задає `RUST_LOG` (типово `info`).

Розширення браузера спілкується з ядром через `downloader-nmhost`. Ядро реєструє його саме під час
кожного запуску; вручну: `downloader-nmhost --install [--allow-extension <ID>]`, де
`--allow-extension` дозволяє додатковий ID розширення (можна повторювати). Інструкція —
[ext/INSTALL.txt](ext/INSTALL.txt).

## Структура

```
crates/core         рушій, планувальник, реєстр протоколів; про UI не знає
crates/proto-http   сегменти, If-Range, повтори
crates/proto-hls    плейлисти, доріжки, розшифрування
crates/proto-dash   MPD: SegmentList і SegmentTemplate
crates/proto-ytdlp  YouTube через зовнішній yt-dlp
crates/ffmpeg       пошук ffmpeg, зміна контейнера, зведення доріжок
crates/ipc          локальний канал: named pipe / unix-сокет
crates/i18n         каталоги перекладів, спільні для всіх оболонок
apps/core-service   ядро-сервіс: черга, події, трей
apps/cli            командний рядок
apps/ui             вікно на Avalonia
apps/nmhost         native messaging host для розширення
ext/chrome          розширення браузера
```

## Правила, які тримають архітектуру

1. **Ядро не згадує жодного протоколу на ім'я.** HTTP, HLS, DASH, торент —
   усе через контракт `Protocol`. Перевіряється тестом із
   протоколом-пустушкою.
2. **Проковтнута помилка заборонена.** `unwrap`, `expect`, `panic` і
   `let _ =` у ядрі відхиляє збірка (`[lints.clippy]`).
3. **Логіка не заповзає в UI.** Усе, що вміє вікно, спершу вміє командний
   рядок.
4. **Помилка називає симптом.** Не «invalid state», а «ресурс змінився,
   докачування неможливе».
5. **Канал лише локальний.** Named pipe або unix-сокет, без TCP-порту
   навіть на `127.0.0.1`.

Коментарі, тексти помилок і назви тестів — українською; назви типів,
функцій і полів — англійською, як заведено в Rust.
